# Deploy Mosaic

The app is a static, no-build deployment. Upload the root files to an HTTPS static host and open `index.html`; `file://` does not provide service worker, install, and offline app-shell behavior. An optional Node.js server is included under `backend/` for same-origin cross-device profile sync.

Included files:

- `index.html` — Mosaic app and its organized player controls
- `mosaic.css` — shared visual system and responsive component styles
- `scripts/` — 22 ordered app modules for core startup, accessibility, onboarding, playback, Reels, profiles, settings, localization, and artwork
- `manifest.webmanifest`, `icon.svg`, and PNG icon sizes — install metadata and app icons
- `sw.js` — caches the app shell, stylesheet, feature scripts, and icons for offline launches after the first visit
- `LOCAL_FIRST.md` — storage boundaries and backend migration outline
- `PLAYER_GUIDE.md` — player feature map and browser/VLC boundaries
- `RELEASE_STATUS.md` — included functionality, validation performed, and integration work still required
- `BACKEND.md` and `backend/` — optional self-hosted profile-sync server and unit checks
- `NATIVE_VLC_WINDOWS_ANDROID.md` — implementation boundary and build plan for native VLC targets

The player uses the browser and operating system decoder. It is not LibVLC and cannot guarantee support for MKV, AVI, FLV, WMV, HEVC, or any particular codec. RTSP, UDP, IPTV protocols, DVD/Blu-ray playback, general transcoding, and recording a network media stream need a native player/backend. Direct web URLs require a browser-playable media response and suitable cross-origin access. Casting, PiP, output-device selection, embedded track selection, and chapter tracks depend on browser support.

Mosaic stores imported file bytes in browser IndexedDB on that device. Profile backups include library metadata, lists, settings, Reels comments, creator follows, language, and watch progress, but not film or music bytes. To move a library, deploy the same Mosaic URL, restore the profile backup, then import the same media files on the other device to reconnect saved item IDs. Direct HTTP(S) media can be saved offline when the source permits CORS and the browser has enough storage. TV mode supports directional-key navigation through visible controls.

The app does not require a backend. To enable cross-device profile sync, including private Reels comments, use the optional Node server described in `BACKEND.md`. Public community comments still need a separate moderated service. The PWA shell can open offline after the first online visit; media storage limits and eviction are controlled by the device.

The first card in **Settings** has separate **Remove demo data** and **Add demo data** controls. They hide or restore Mosaic's bundled preview titles for the current profile; imported media, playlists, and saved titles are preserved. Demo cards now include genre, year or content rating where relevant, clearer descriptions, and distinct generated artwork.

Profile management supports initials, colours, renaming, and per-profile avatar symbols. Avatar preferences sync with profile settings when cross-device sync is configured. Help includes searchable answers for Reels gestures, film and music controls, profile setup, samples, and theme behavior.

Choose English or Hindi from **Settings → Language**. The current Hindi dictionary covers common navigation, settings, player, search, Reels, Lab, and system-check labels. Untranslated labels and all media titles, comments, and other user content remain in their original language. This is an initial localization pass, not a complete translation review.

Open **Help → Run system check** to inspect local storage and browser support for audio, voice search, recording, PiP, casting, folder import, and the offline app shell. If a sync service is configured, it sends a small ping to check reachability; it never reads media filenames or transmits the report.

This ZIP is a web/PWA deployment. The player uses the browser media decoder; it does not embed LibVLC. See `NATIVE_VLC_WINDOWS_ANDROID.md` for the separate native work required for a true VLC decoding engine on Windows and Android.

After deployment, open the HTTPS URL once while online, then use the browser's install option if desired. Confirm the host serves `.webmanifest` as JSON and `sw.js` as JavaScript; most static hosts configure these automatically.


## Deploy on Netlify (static app + sync function)

1. Push this folder to a Git repo (or use Netlify CLI `netlify deploy --prod`). `netlify.toml` is included: publish directory `.`, functions in `netlify/functions`, `/api/sync` served by the `sync` function, `sw.js`/`index.html` set to no-cache, and `/backend/*` hidden.
2. `package.json` declares `@netlify/blobs`; Netlify installs it during the build. Sync data is stored in a Netlify Blobs store named `mosaic-sync` (no database or other hosting needed).
3. The app calls `/api/sync` on the same origin, so no configuration is required. Run `node --test netlify/functions/sync.test.mjs` for the function checks (uses an in-memory store).
4. The Node server in `backend/` remains available for self-hosting but is not used on Netlify. Netlify Blobs writes are last-write-wins at the storage layer; the app's version check (`expected` vs stored `t`) still rejects stale writes in normal use, but two simultaneous writes from different devices in the same instant could both pass.
